Kepler Browser Integration Guide

Official contract for Kepler College web systems (IGA, MIS, and future institutional platforms) to detect Kepler Browser, trigger proctored exam lockdown, and distribute dynamic app policies.

Overview JavaScript API postMessage Fallback Exam Lifecycle Remote Config JSON Server Enforcement

1. Architecture Overview

Kepler Browser is a standalone Chromium-based desktop browser that students use daily. Rather than coupling the browser to private LMS internals, the browser defines a clean, stable contract that any authorized Kepler system can invoke:

  • Normal Mode: Full multi-tab browsing, bookmarks, downloads, and SSO logins.
  • Examination Mode: Safely stashes all open tabs in memory, enters fullscreen lockdown, blocks unauthorized navigation/shortcuts/clipboard/printing/downloads/DevTools, and restores all tabs on completion.
  • Origin Authorization: Only origins configured with canInitiateExam: true in config.json can request Examination Mode.

2. JavaScript Integration API (window.keplerBrowser)

Kepler Browser injects a read-only window.keplerBrowser object into the top-level frame (never into nested third-party iframes).

Detect Kepler Browser

if (window.keplerBrowser?.isKeplerBrowser) {
  console.log('Running inside Kepler Browser v' + window.keplerBrowser.version);
}

Start a Proctored Examination

Calling requestExamMode() opens the browser's Pre-Exam Security Check modal. The Promise resolves once the student confirms and fullscreen lockdown is active, or rejects if cancelled/unauthorized. 

try {
  const { sessionId } = await window.keplerBrowser.requestExamMode({
    allowedDomains: ['*.igaafrica.com'],
    examUrl: 'https://keplercollege.igaafrica.com/courses/3155/content/quiz/101/',
    title: 'STAT-201 Midterm Examination',
    durationMinutes: 60
  });
} catch (err) {
  // Student cancelled security verification or origin is not authorized
}

Check Active Exam Status

const status = await window.keplerBrowser.getExamStatus();
// { inExamMode: true, sessionId: '...', title: 'STAT-201 Midterm Examination' }

Complete Examination & Release Lockdown

Call completeExam() from the locked examination page after the server confirms submission. Only the active locked exam view on the authorized LMS origin is permitted to unlock the browser. 

await window.keplerBrowser.completeExam();

3. Declarative window.postMessage Protocol

Systems that prefer message passing can send same-origin top-frame messages using the kepler: prefix: 

// Request exam lockdown
window.postMessage({
  type: 'kepler:request-exam-mode',
  payload: {
    allowedDomains: ['*.igaafrica.com'],
    examUrl: window.location.href,
    title: 'Midterm Assessment'
  }
}, window.location.origin);

// Signal exam completion
window.postMessage({ type: 'kepler:exam-complete' }, window.location.origin);

// Listen for browser responses
window.addEventListener('message', (event) => {
  if (event.origin !== window.location.origin) return;
  if (event.data?.type === 'kepler:exam-mode-entered') { /* locked */ }
  if (event.data?.type === 'kepler:exam-mode-exited')  { /* unlocked */ }
  if (event.data?.type === 'kepler:error')             { /* handle error */ }
});

4. What Happens During Examination Mode

ControlBehavior in Examination Mode
Tabs & Address BarHidden; existing student tabs are muted and safely stashed in memory until exam completion.
Fullscreen & FocusFullscreen enforced; exiting fullscreen or switching apps triggers the Security Interruption screen.
Navigation & PopupsStrict domain allowlist enforced silently on navigation, redirects, and window.open().
Clipboard & PrintingClipboard cleared and blocked (shortcuts + DOM + navigator.clipboard); printing disabled.
Downloads & DevToolsSession downloads blocked; DevTools disabled; context menu suppressed.
Native OS LockdownOn macOS builds signed with Apple's Assessment entitlement, engages AEAssessmentSession automatically.

5. Dynamic Remote Policy Config (config.json)

Kepler Browser can sync institutional applications and exam-authorized origins from a static HTTPS JSON file without rebuilding the desktop app — no backend API required.

Live public config endpoint alongside these docs: ./config.json — paste its HTTPS GitHub Pages URL into kepler://settings → Remote Policy Configuration (or set KEPLER_CONFIG_URL). 
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-23T12:00:00Z",
  "applications": [
    {
      "id": "iga",
      "name": "Kepler IGA",
      "url": "https://keplercollege.igaafrica.com/auth/dashboard/",
      "enabled": true,
      "pinned": true,
      "securityProfile": "dynamic",
      "allowedDomains": ["*.igaafrica.com"],
      "canInitiateExam": true
    }
  ]
}

6. Server-Side Approved Browser Enforcement

Client-side browser checks alone cannot stop a student from typing an IGA URL into Chrome or Firefox. For high-stakes exams, institutional backends should pair Kepler Browser with:

  • Short-lived, signed assessment launch tokens tied to the authenticated student session.
  • Server-side validation of assessment lifecycle timestamps and interruption events.
  • Never relying solely on a custom HTTP User-Agent string as proof of lockdown.
